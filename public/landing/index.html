How it works

Four layers, one engine, one gate

Everything an agent can do goes through the same desk session: observe, analyze, plan, approve, send. Every order crosses the same policy matrix. MCP and the web UI share one process — what your agent does is what the dashboard shows.

01

Market observer

Live ticker, depth, 1h/4h candles, 20-symbol tape, Web3 pulse boards.

02

Research engine

Technical snapshot, RSS headlines, Fear & Greed, scored bias — no hallucinated prices.

03

Policy gate

BLOCK, UNKNOWN, or CLEAR with every rule visible. Missing data never treated as zero.

04

Agent OS bridge

EXECUTE mints a one-time token. Agent OS sends exact packet fields + HMAC stamp.

Observe

Pull live Spot evidence, Web3 boards, and optional analysis report.

Plan

Size quantity to lot step, tick, and min-notional. Gate runs immediately.

EXECUTE

Single-use approval token (60s). Nothing sends until you type the phrase.

Reconcile

Hash-chained receipts classify AUTHORISED vs FOREIGN / FORGED / MISMATCHED.

Safety by construction

Fail-closed gate, every verdict with a reason

Hosted demo runs without API keys — observe and plan only. Your balance is never exposed on the public URL.

VerdictMeaning
BLOCKHard rule failed. No approval, no send.
UNKNOWNRequired fact missing (usually balances). Plan allowed; send refused.
CLEARGate open — you still must type EXECUTE.

HMAC order stamps

Every approved packet carries boss_<seq>_<mac>. Copying the prefix is not enough.

Scope burn

FOREIGN / FORGED / MISMATCHED orders burn trade scope until restored from the desk.

Default caps

100 USDT per order · 500 USDT per UTC day · Spot only · withdrawals never.

What BOSS never does

Send without EXECUTE

Approval tokens are single-use and expire in 60 seconds.

Invent a price

If Binance is unreachable, BOSS stops — no placeholder fills.

Change your packet

Agent OS must send the exact fields BOSS approved, including the stamp.
